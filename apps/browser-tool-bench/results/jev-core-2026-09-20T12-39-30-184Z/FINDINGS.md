# Jev 优先执行：36 次尝试的结论

复用 Garden Lab 的六张原任务卡，每题两种模式、三轮。Jev 优先组通过 17/18，Kimi / Claude Agent SDK + Jev 辅助组通过 18/18。浏览器 CDP 会话归属错误为 0；第 32 次出现一次任务超时收尾异常，中断后保留该条失败，只继续余下四条，未用重跑结果替换失败。

## 能确认的价值

实时事件任务的三次 Jev 优先耗时为 14.0、13.7、17.9 秒，对照为 42.4、44.8、56.4 秒，均通过。它适合以明确页面按钮触发操作、等待短响应、读取清晰回执的任务。这三次均无需启动完整 SDK，但仍调用 Kimi 做最终生成式核查。

Jev 优先组有 **15/18 次启动了完整 SDK**。这次测的是整个产品执行方式，并非两个模型的独立推理速度。观察链路、任务上下文、辅助调用都不同：driver 回退后不再逐页做 Jev 辅助判断；advisory 则继续做。上传三次都直接回退，不能把其时间差说成 Jev 自己上传文件更快。

当前数据支持保留“Jev 负责简单页面动作、Kimi 负责生成和复杂步骤”的组合；尚不支持宣称 Jev 能稳定独立处理全部浏览器任务，也不能外推为优于 Codex 或真实淘宝、BOSS 等网站。每题仅三轮，未作统计显著性判断。

## 失败与优化方向

1. **动态加载被过早判为没有进展。** T05 三轮均回退。第一轮快照中的动态从零条增长到三条，流程却因指纹连续相同回退。当前进度判断复用了控件操作有效性指纹，它不覆盖全部正文。应把操作安全校验与正文进度判断分开。
2. **结果已出现仍继续等待。** T20 的记录已显示全部十轮和汇总，Jev 仍选 WAIT 后回退。可以在连续等待达到阈值时先进行一次有上限的完成核查；核查不通过再启动完整 SDK。
3. **登录和文件上传存在明确回退边界。** 快速候选不包含密码、文件输入，也不遍历 Shadow DOM。T08 三轮由 SDK 完成密码和后续领取；T18 三轮一开始就交由 SDK 处理。
4. **分页提取的交付不稳定。** T06-driver-r3 在生成文件后重新导航和翻页，最终返回 partial。文件的 12 项商品数值与排序正确，但采用 columns/rows 对象，不符合要求的 name/price/stock 对象数组；完成依据还使用了无法在当前 AX 快照中逐字匹配的合并文本。应改进生成结果格式与完成证据表达，而不能降低正确性标准来增加通过率。
5. **任务结束后的定时器异常。** partial 已持久化、SDK 仍未退出时，四分钟回调调用 pause，被“任务已经结束”拒绝，未处理拒绝使评测进程退出。该条缺失独立验收和最后 SDK 用量，240 秒仅为时限截尾标记，不进入成功耗时统计。详见 [中断记录](RUNTIME-INTERRUPTION.md)。

前四项是本次测出的待优化点。第五项已在全部 36 次尝试结束后修复，且通过回归验证；没有更改本次成绩，详见 [评测后修复](POST-BENCHMARK-FIX.md)。

## 复现边界

所有 36 个格子的产品运行代码哈希在收尾时与原 manifest 一致，见 [冻结验证](frozen-runtime-verification.json)。恢复仅修改评测脚本以跳过已尝试的 32 条。旧预试验与旧中断批次均单独保留，不混入本次数据。

SDK 估算费用既不含 Jev / 直接辅助调用，也缺少中断记录的最终用量，不能据此得出总费用节省结论。本次在 Windows 实测；未执行 macOS 浏览器实测。
