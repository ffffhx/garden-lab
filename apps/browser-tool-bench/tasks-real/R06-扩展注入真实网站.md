# R06 · 扩展注入真实网站

- **测试维度**：插件 content script、`chrome-extension://` options 页、真实网站注入验证
- **目标网站**：`https://ffffhx.github.io/garden-lab/post/agent/`
- **登录态要求**：不需要登录
- **写入风险**：只允许写入专用测试 profile 中 Bench Badge 扩展的本地 storage；不得修改目标网站

## 前置准备

1. 使用干净 Chrome for Testing / Chromium 专用 profile，加载 `apps/browser-tool-bench/extension-sample/`。
2. 不使用企业管控的系统默认 Chrome 作为扩展宿主；企业策略可能拦截 unpacked extension 注入。
3. 打开目标网站后应能看到右下角 `BENCH EXT v1.0.0` 徽标。

## Prompt（逐字使用）

> 当前测试浏览器已经加载 Bench Badge 扩展。请打开 https://ffffhx.github.io/garden-lab/post/agent/ ，确认页面右下角有扩展注入的徽标；然后打开这个扩展的设置页，把徽标文字改成 REAL-SITE-2026 并保存；最后回到这篇真实线上文章刷新页面，告诉我徽标完整内容和最终 URL。

## Ground Truth

- 初始徽标：`BENCH EXT v1.0.0`。
- 保存后刷新真实网站页面，徽标应为：`REAL-SITE-2026 · v1.0.0`。
- 目标网站内容本身不应被修改；只变更扩展在测试 profile 里的本地配置。

## 判定标准

| 等级 | 条件 |
| --- | --- |
| ✅ 成功 | 通过扩展设置页 UI 修改配置，并在真实线上页面验证注入结果 |
| ⚠️ 部分 | 修改成功但没在真实网站验证；或绕过设置页直接写 storage |
| ❌ 失败 | 无法到达 `chrome-extension://` 设置页，或扩展没有注入真实网站 |
| N-R | 当前浏览器不能加载 unpacked extension |

## 记录指标

轮数 / 时间 / 扩展 ID 发现路径 / 是否能枚举 extension target / 是否触发企业策略拦截。
