# R08 · 真实网站请求拦截

- **测试维度**：真实网站 route / abort / mock 能力、资源降级验证
- **目标网站**：`https://developer.mozilla.org/en-US/docs/Web/API/Fetch_API`
- **登录态要求**：不需要登录
- **写入风险**：无；只允许本地浏览器拦截资源请求，不得攻击或压测目标网站

## Prompt（逐字使用）

> 打开 https://developer.mozilla.org/en-US/docs/Web/API/Fetch_API 。请在浏览器层拦截这个页面的图片资源请求（例如 image resource type 或常见图片扩展），让至少一个图片请求被本地 abort / block；随后确认主文档仍然加载成功，页面标题仍然是 Fetch API 相关内容。请报告被拦截的请求 URL、拦截方式和最终页面标题。

## Ground Truth

- 成功时至少有一个图片资源请求被本地拦截或 abort。
- 主文档仍应加载 Fetch API 文档页。
- 这道题考的是网络层拦截；单纯用页面 CSS 隐藏图片不算成功。

## 判定标准

| 等级 | 条件 |
| --- | --- |
| ✅ 成功 | 使用工具的 route / abort / intercept 能力拦截真实网站资源，并验证页面降级后仍可读 |
| ⚠️ 部分 | 通过 JS / CSS 层隐藏图片，但没有网络层拦截 |
| ❌ 失败 | 工具不支持拦截，或导致主文档无法加载 |
| N-R | 当前工具明确没有 route / abort 能力且无法表达该操作 |

## 记录指标

轮数 / 时间 / 拦截规则 / 被拦截 URL / 是否有 HAR / Network 证据。
