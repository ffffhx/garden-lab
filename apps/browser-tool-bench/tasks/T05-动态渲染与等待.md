# T05 · 动态渲染与等待：流式列表计数

- **测试维度**：快照时机、等待策略、多步操作闭环（对应文章第 2 节）
- **适用工具**：全部
- **靶场页面**：`/livefeed`

## Prompt（逐字使用）

> 打开 http://localhost:4399/livefeed ，把所有动态都加载完（包括点"加载更多"之后的），然后告诉我：页面上最终一共有多少条动态？最后一条动态里的口令是什么？

## Ground Truth

- 第一页 8 条，逐条渲染（每 250ms 一条），全部渲染完才出现「加载更多」按钮。
- 点击后第二页再加 4 条，同样逐条渲染。
- 最终 **12 条**；最后一条是「系统公告：今日口令 **LIVE-512**」。

## 判定标准

| 等级 | 条件 |
| --- | --- |
| ✅ 成功 | 12 条 + LIVE-512 都正确 |
| ⚠️ 部分 | 只对一半（典型错误：快照太早数成 8 条，或第二页没渲染完就数） |
| ❌ 失败 | 没找到"加载更多"按钮或两问皆错 |

## 记录指标

轮数 / token / 时间；额外记录重试快照的次数（反映"工具是否帮 Agent 处理等待"）。

## 预期差异点

按钮出现前快照里没有它。验证各工具的策略：自动等待（Playwright actionability）、Agent 主动轮询快照（agent-browser）、还是一次快照就回答（容易翻车）。
