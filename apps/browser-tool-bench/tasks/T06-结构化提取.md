# T06 · 结构化提取：把商品目录整理成 JSON

- **测试维度**：页面阅读成本、结构化输出、翻页（对应文章第 7 节，bb-browser site adapter 的对照组）
- **适用工具**：全部
- **靶场页面**：`/catalog`

## Prompt（逐字使用）

> 打开 http://localhost:4399/catalog ，把全部商品（注意有第二页）整理成 JSON 数组，每项包含 name、price（数字）、stock（数字），按 price 从高到低排序。最后告诉我最贵的商品是什么、多少钱。

## Ground Truth

- 共 **12** 件商品，第 1 页 8 件 + 点「加载第 2 页」后 4 件。
- 最贵：**雷霆工作站，15999 元**（在第 2 页）。
- 价格在页面上显示为「¥ 15,999.00」格式，需要清洗成数字；有两件商品带「缺货」徽标（stock 为 0）。
- 完整排序（price 降序）：雷霆工作站 15999 → 全画幅扫描仪 3699 → 4K 专业显示器 2499 → 人体工学椅 1899 → 会议级摄像头 1599 → 桌面监听音箱 1299 → 降噪耳机 Pro 899 → 便携 SSD 1TB 749 → USB-C 扩展坞 549 → 电竞鼠标 459 → 静音机械键盘 399 → 智能护眼台灯 329。

## 判定标准

| 等级 | 条件 |
| --- | --- |
| ✅ 成功 | 12 条全、字段干净（price/stock 是数字）、排序对、最贵答对 |
| ⚠️ 部分 | 漏了第二页（只有 8 条），或价格没洗成数字 |
| ❌ 失败 | 数据大面积错误 |

## 记录指标

轮数 / token（重点指标：读 DOM 提取 vs 直接看 /api/products 响应，token 差距会很大）/ 时间。

## 预期差异点

聪明的路径是发现数据来自 `/api/products` 接口直接拿 JSON；笨路径是读 DOM 慢慢抠。记录每个工具引导 Agent 走了哪条路——这正是文章第 7 节"adapter 价值"的微缩版。
