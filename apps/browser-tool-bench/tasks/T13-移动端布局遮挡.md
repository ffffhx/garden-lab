# T13 · 移动端布局遮挡

- **测试维度**：移动端 viewport、点击失败复盘、CSS computed style / z-index / overlay 排查
- **适用工具**：全部；能调 viewport 和截图/布局信息的工具更有优势
- **靶场页面**：`/layout-mobile`

## Prompt（逐字使用）

> 把浏览器视口设为移动端 390×844，打开 http://localhost:4399/layout-mobile 。尝试点击"提交支付"。如果点不到或没有出现确认码，请定位是哪一个元素遮挡了按钮，说明关键 CSS 原因，并告诉我正常点击后应该出现的确认码。

## Ground Truth

- 移动端 CSS 下 `.checkout-actions` 固定在 `bottom: 40px; z-index: 10`。
- `.mobile-support-bar` 固定在底部，高 `118px`，`z-index: 20`，覆盖在支付按钮上方并吞掉点击。
- 遮挡元素：**`.mobile-support-bar[data-bug="overlaps-pay-button"]`**。
- 正常触发按钮后显示：**`支付确认码：MOBILE-39`**。

## 判定标准

| 等级 | 条件 |
| --- | --- |
| ✅ 成功 | 说明遮挡元素、z-index/position 原因，并报出 MOBILE-39 |
| ⚠️ 部分 | 能看出按钮被遮挡，但没有定位具体 selector 或 CSS 原因 |
| ❌ 失败 | 认为按钮本身不可用、或直接用 JS 强点后只报确认码 |

轮数 / token / 时间；记录是否使用移动 viewport、截图、元素盒模型或 computed style。
